# K3s传输统计与调度观测修复（0.5.1）

日期：2026年11月8日。范围：修复用户反馈的“传输统计缺失、调度显示带宽未提供”。保持任务内每节点一个容器、模型加载一次的B模式。

## 核查结论

这是容器迁移时的数据链路遗漏，不是主动取消带宽统计。

1. 容器入口已经测量并回传 `input_bytes`、`download_seconds` 和 `observed_transfer_mbps`，但既有网页只读取旧进程执行器的 `input_transfer_seconds`，导致下载耗时和接收速率显示为空。输入量、推理吞吐等字段并非全部缺失。
2. K3s节点快照只从历史成功结果回填推理吞吐，没有把已有下载观测接回 `bandwidth_mbps`。正式资源池接口当前未启用，因此调度没有网络速率输入，传输成本未参与资源感知评分。页面的未知状态符合当时数据，但数据反馈链路本身漏接了。
3. 上一轮统计测试沿用旧进程结果格式，未覆盖真实容器输出到统计页面的字段一致性。本次补充旧容器格式、新格式以及真实K3s任务回归。

例：修复前最新成功分片已记录193,034字节、下载0.0668565秒、有效接收速率约23.10 Mbit/s，对应节点快照仍为“未测量”。

## 修复内容

- 新B容器统一回传 `input_transfer_seconds`，同时保留 `download_seconds` 兼容字段。网页兼容两种格式，已有容器任务无需重跑即可显示下载统计。
- K3s节点快照使用同一集群、同一Node UID在近300秒内最多8个成功分片，按总输入字节数除以总下载耗时计算有效速率，并供资源感知调度估算本片输入传输时间。正耗时低于1毫秒时统一按1毫秒计算；无效值不参与。
- 样本时效保守使用服务器记录的分片执行开始时间，避免把漫长推理后的结果回传时间当成下载时间，也不依赖不同节点的时钟同步。样本超过5分钟后不再用于评分，等待新成功分片。节点替换或跨集群不能复用旧节点样本。
- 节点快照与每次调度记录保存观测来源、样本数、样本时间、失效时间和尝试ID。调度前再检查样本有效期。资源池以后若明确提供带宽值，优先使用资源池值及其来源，不混用本地样本元数据。
- 调度页面改为说明“暂无有效传输观测”的具体来源；已有观测时显示预计传输耗时及其依据。传输页补充样本时间、样本数和有效期，并修正为当前K3s容器网络环境。
- 历史任务结果和历史调度快照均不改写。旧任务可恢复结果统计，但旧决策当时没有带宽输入，仍然显示未知。

## 使用与理解

刷新网页，打开“任务详情 → 传输与吞吐”，可查看输入量、下载耗时、有效接收速率和处理吞吐。已有A/B容器任务也适用。

新建多分片任务时，若节点还没有近期成功样本，最初若干次调度会显示未知；完成分片并刷新节点快照后，后续调度使用观测值。冷启动阶段按既有计算与排队估计分配，不把未知带宽伪造为实测值。资源感知算法使用传输成本；轮询算法仍按轮询选择，记录估计仅用于解释。

这里的速率是“管理服务/内部网关 → 执行容器”的应用有效下载速率，包含请求、必要重试等待及写本地文件时间，并非网卡额定带宽、瞬时可用链路容量或真实车载无线带宽。统计只涵盖当前有效成功分片的输入下载，不包含镜像拉取、结果上传和失败尝试流量，也不是并发总带宽。

HTTP往返耗时是另一项观测。旧进程路径通过worker健康请求采集，当前K3s路径未单独探测容器数据通路，仍显示“—”；不把K3s控制面请求耗时替代为该指标。
