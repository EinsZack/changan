# 内存需求范围修复

2026年11月4日，版本0.3.1。

## 问题与修复

候选筛选输入999999 MiB时返回422，原因是后端TaskInput及候选筛选、新建任务两个前端输入框均将最低内存上限写死为65536 MiB。当前服务器节点可用内存超过该数值，64 GiB上限不适用于实际资源。

本次移除后端和两处输入框的固定上限，最低值仍为64 MiB且必须是整数。候选筛选表单增加原生校验，空值、低于64或小数在提交前提示。内存需求超过当前资源时，查询正常返回200，调度器按节点快照给出“可用内存不足”。TaskInput由普通任务、候选查询与策略共用，三类入口同步支持大内存值。

## 验证

- 47项后端测试通过，含7项大内存回归，覆盖65537、999999、1048576、1048577 MiB及下限和整数限制；普通任务和策略保存999999参数正确。
- 6项前端测试及生产构建通过。
- 隔离服务真实浏览器输入131072 MiB得到4个可行节点；999999 MiB请求成功，4个节点按当时约801934—801941 MiB可用内存返回“可用内存不足”。
- 新建任务页面可输入999999 MiB；实际以131072 MiB创建task_17437ff9726d424b并完成48帧。浏览器脚本错误为0。
- 发布0.3.1前确认主环境无在途任务，重启管理API。原执行器与Redis继续运行。前端旧构建位于tmp/pre-memory-limit-fix-web-dist-20261104。

刷新网页后直接输入所需最低内存，单位MiB。超过节点可用内存时查看筛选理由，无需将需求压低到65536。
