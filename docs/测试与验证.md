# 中期原型测试与验证

版本：0.1.0。验证日期：2026-09-30（上海时区）。代码目录：`/root/projects/changan-orchestrator`。

## 1 验证结论和适用范围

本轮已验证服务器上的视频任务闭环、候选过滤、真实CPU目标检测、多进程执行、有限重试、取消、进程重启后的状态恢复、触发策略、五类固定能力模板和网页操作。测试环境为同一Linux x86_64开发服务器上的1个协调服务、4个独立HTTP执行器进程及Redis单机，**不是4块真实车端板卡**。

所有识别结果由YOLOX Tiny ONNX实际推理生成；资源侧使用执行器观测和本地预留。资源池外部适配仅做模拟HTTP契约测试，尚未接入同学的正式服务。没有车端硬件、异构集群、真实跨车网络和最终性能验收结论。

### 2.1 状态与契约测试覆盖

- 候选约束：健康、时效、可用槽位、内存、模型、架构、标签、指定节点、位置；算法输入输出可解释。
- 幂等：同一个提交键返回同一个任务；同键不同参数拒绝；16个并发相同请求只生成一个任务。
- 状态：重复/乱序回调、错误实际节点、旧尝试、已取消父任务、重试上限、聚合缺片；失败回调保留执行ID及实际节点，重复失败不增加重试次数。
- API：任务校验、路径限制、策略操作、配置注册、API密钥及浏览器会话、跨站修改拒绝。
- 连接器：环境Bearer插件每次解析环境、键映射；资源池快照、幂等预留和释放的客户端契约。

## 3 重复基线原始测量

输入为OpenCV样本的前24秒，768×576、10fps；每片4秒，总计6片，推理采样2fps，置信阈值0.35，YOLOX Tiny COCO 416、ONNX Runtime CPU。三种配置按轮次顺序执行，测量时未并行运行本项目的浏览器/集成测试；服务器仍为共享设备，其他项目负载不受本项目控制。

测量值为父任务创建至终态的墙钟耗时，包含等待、视频切分、调度、传输、推理、回传、聚合和轮询间隔；不是纯算法耗时。网络为同机HTTP回环。执行器模型已加载，未控制操作系统缓存，不能外推到真实车端。

| 配置 | 第1次 / 秒 | 第2次 / 秒 | 第3次 / 秒 | 平均 / 秒 | 范围 / 秒 |
|---|---:|---:|---:|---:|---:|
| 单执行器 | 12.140 | 9.767 | 14.567 | 12.158 | 9.767—14.567 |
| 四执行器轮询 | 6.623 | 6.020 | 6.318 | 6.321 | 6.020—6.623 |
| 四执行器资源感知 | 7.194 | 8.118 | 7.034 | 7.449 | 7.034—8.118 |

本次测量中多执行器平均耗时低于单执行器，**基础资源感知算法没有优于轮询**。同质执行环境、估计误差、轮询间隔和共享负载都会影响结果；样本量只有各3次，未做统计显著性检验，不形成普适加速承诺。

9次输入SHA256均为`e61fdd9e19f04d903e180204a7d0e54e0a0bef79b479123619117e299d1a13fb`。每次分析48个采样帧，person为299、car为48、truck为48，其他目标类别为0。此处是采样帧内目标出现次数累加，**不代表唯一人数、唯一车辆数或识别精度**；没有人工标注真值，不能据此给出准确率。

候选选择计算耗时与`dispatch_batch`一轮分配/提交耗时分别保存。本轮未把二者混同为甲方“单次全局决策≤10s”；也未把9次成功或业务完成率当成“预设时限内调度成功率≥99%”。这两项需冻结口径后在真实环境系统验证。

## 5 复验方式

进入服务器并激活专用环境，按以下顺序执行；集成测试会重启本项目进程，需确保没有其他在途业务。

```bash
cd /root/projects/changan-orchestrator
source /root/miniforge3/etc/profile.d/conda.sh
conda activate changan-orchestrator
python scripts/manage.py start
python -m pytest -q
python scripts/integration.py
python scripts/benchmark.py
cd web
npx playwright test
```

基线期间保持周期策略停用，避免并行创建任务。首次浏览器安装方法见《使用说明》。测试再次运行会更新报告并新增历史任务，不覆盖旧任务实体。
