# 中期原型演示脚本

建议用时8—12分钟。演示环境为4个服务器进程执行器，真实运行视频分析；开场即说明尚未替代真实车端验收。

## 演示前

- 启动系统，检查4个执行器在线、无其他正在执行的任务。
- 打开SSH隧道及浏览器。
- 保持周期策略停用，避免干扰基线对比。
- 确认数据目录和既有测试记录保留；不要为了界面好看删除失败记录。

## 演示顺序

1. **总览（1分钟）**：介绍任务、资源池和执行器的分工。资源池正式服务由同学提供，当前开发适配明确标识。
2. **提交（1分钟）**：选择固定24秒视频、4秒切片、2fps、置信度0.35，提交实际任务。
3. **工作流（1分钟）**：看到切分、调度、执行、聚合。显示6个必要片段和多个节点实际并行时间段。
4. **决策（1分钟）**：打开一次分配，核对候选节点、约束、估计来源、目标节点与实际节点。解释计算耗时与完整全局决策验收口径的区别。
5. **结果（1分钟）**：打开带真实检测框的图片和原视频，说明统计为采样帧目标出现次数。下载含模型哈希、片段和尝试ID的证据。
6. **异常（2分钟）**：给一个测试执行器注入一次失败，再运行一条任务。查看失败记录、新尝试和最终聚合。若未选中该节点，可选择该单节点运行以确保演示发生，不能伪造错误动画。
7. **历史与对比（1分钟）**：选择已完成的同输入单执行器和多执行器运行，展示实际耗时比及原始记录。解释共享服务器负载和回环网络限制。
8. **触发与能力（1分钟）**：服务策略触发一次任务，展示周期历史记录及策略ID；运行五类能力验证，打开Redis读写和脚本退出码。
9. **后续联调（1分钟）**：展示接口文档，明确下一步接入4个真实车端、资源池预留机制、正式模型和网络条件。

本交付包含浏览器自动流程录屏，文件由测试直接产生；它是验证过程记录，不是现场真车端演示录像。正式汇报前可按照此脚本再录制讲解版。
