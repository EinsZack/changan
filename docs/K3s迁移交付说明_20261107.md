日期：2026年11月7日　版本：0.4.0

## 交付结果

用户确认计划后，已在服务器 /root/projects/changan-orchestrator 将当前视频执行链路迁移到 K3s Job 模式，并切换实际运行服务。旧四进程 worker 已停止；管理服务、内部容器网关和 Redis 继续运行，64 条历史任务完整保留。

当前开发集群为 1 个 K3s 控制节点、4 个逻辑执行节点。Docker 构建镜像，内部 registry 提供分发，K3s 节点中的 containerd 执行视频 Pod。四个逻辑节点均在同一服务器，不是四块 THOR 实机。

~~~mermaid
flowchart LR
    UI[任务页面] --> API[任务编排与业务调度]
    API --> K[K3s Job / 节点约束]
    Build[Docker构建模型与环境] --> Registry[镜像仓库]
    Registry --> Pod[目标节点的视频Pod]
    K --> Pod
    Pod --> Gateway[尝试认证与产物网关]
    Gateway --> Store[数据库与结果文件]
    Store --> UI
~~~

## 代码变化

| 部分 | 实现 |
|---|---|
| 镜像交付 | Dockerfile.video、固定依赖、模型文件，按不可变镜像摘要发布；任务冻结应用和模型身份 |
| 执行后端 | 新增 Kube API 适配和容器执行控制器；每个分片尝试对应 Job，保留 Job/Pod UID 与实际节点 |
| 自有调度 | 继续使用基础资源感知/轮询策略，通过 nodeSelector 和必选节点亲和性交给 Kubernetes 调度 |
| 节点资源 | 读取真实 Node/Pod 状态，使用业务预算；可与资源池快照合并，K3s预算和资源池约束均需满足 |
| 容器入口 | 单次任务入口下载输入、校验摘要、加载模型、推理、上传产物并退出；没有常驻 HTTP worker |
| 状态与恢复 | 区分镜像准备、容器启动、模型加载、推理、上传和核验；重启后根据持久化身份恢复 |
| 一致性 | 尝试令牌与 Pod UID 认领，重复 Pod 不得执行；事件序号去重，跨进程观察合并，阶段不倒退 |
| 清理与重试 | Job不自动重试；业务层在旧 Pod 清理后重试，控制面或节点状态未知时保留槽位 |
| 结果 | 先上传并校验产物，再核验容器成功退出，最后聚合；容器结束不直接等于业务成功 |
| 前端 | 真实节点类型、动态节点选择、容器与镜像页签、清理状态、失败日志、历史进程任务兼容 |
| 运维 | 项目内Docker daemon、集群安装/配置/镜像构建脚本、受限RBAC、资源配额和内部回传网络策略 |

主要入口为 app/kube.py、app/container_execution.py、app/container_api.py、workers/container_entry.py、deploy/ 和 scripts/ 下的 K3s 脚本。旧进程后端仅为历史和回归保留，默认执行后端为 k3s。

## 使用与双方联调

日常使用入口保持原有 SSH 隧道和 127.0.0.1:8310。新任务在“容器与镜像”页签查看身份、镜像、落点、阶段及清理记录。详细启停、复现、配置和回退见《K3s部署与使用说明》。

方雍的业务边界是任务规范、分片、调度决策、Job适配、结果和页面；与顾强强共同确认节点ID标签、镜像仓库、资源预算、资源池快照及租约接口。当前尚未对接顾强强的正式资源池服务，保留了适配契约；正式共享资源池需一并确认长时间失联时的租约续期与设备隔离策略，不能只依靠原有有限租期。

## 验证边界

本次完成的是现有视频任务的容器化迁移。仍使用 YOLOX Tiny / CPU ONNX；其他应用需要新增镜像及输入输出契约，尚不是任意代码和任意模型发布平台。

THOR板卡尚未到位。ARM64、GPU运行时和GPU推理后端、真实车载网络及4板协同需要到货后验证。当前镜像仅支持 amd64，架构不符的节点不会进入候选集合。

管理服务与SQLite仍为单实例，开发仓库使用内部HTTP网络；正式多机部署需要配置真实网络、仓库TLS和凭据管理。外层开发容器没有systemd，外层服务器重启后需按使用说明启动集群及业务服务。

## 环境处理留痕

首次搭建发现并修复了外层开发容器的cgroup资源委托问题；所有处理局限于当前容器名字空间。嵌套环境继承的宿主大页预留导致小内存节点可调度内存为零，因而节点容器上限调整为8GiB，业务预算保持每节点3GiB及1槽。基础镜像通过受控预装解决外网下载受限。上述基础设施调试产生的初期尝试保存在隔离数据库，未计入稳定版本验收结果。
