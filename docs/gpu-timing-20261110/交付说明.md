# GPU视频推理与分段计时交付说明

2026年11月10日，基于8979c48完成0.5.2，已部署服务器/root/projects/changan-orchestrator的正式8310服务。本地只同步说明、计划与验证证据。

## 已实现

- 原lab-1～4继续使用同一类通用CPU/GPU容器。会话Pod在节点具备GPU时声明NVIDIA运行时与设备；模型层默认auto尝试CUDA，按容器内可见索引选卡。没有新增gpu-1或任务级专用节点选择。
- 初始化成功须同时满足实际执行提供程序及预热CUDA计算事件；关闭运行期整模型静默回退。auto初始化失败则明确记录原因并使用CPU，后续分片保持实际后端一致。
- 保持B模式：每任务/节点一个Pod、模型加载一次、多分片连续处理，任务后回收。会话及分片的身份、模型/输入/产物校验和异常隔离保持。
- 持久记录Job提交、Pod创建/调度、镜像事件、容器启动、程序初始化、模型加载/预热；镜像缓存命中与实际拉取分别展示，未采集阶段保持未知。
- 分片记录下载、视频分析、产物上传；分析中记录解码、预处理、模型前向、后处理、预览生成与其他操作，以及逐帧前向区间。
- 网页“工作流与执行”新增启动与推理时间轴、阶段明细、实际设备及CPU回退原因。“历史与对比”补充初始化、分析与帧均前向。旧记录不补造分段数据。
- 实测暴露旧1GiB主机内存限制不足，统一CPU/GPU运行环境的新应用预算改为2GiB，并同步候选筛选、会话预留、Pod请求和限制。该值仍须在THOR上重新实测。

## 实测结论

同镜像、单lab-1、相同CPU和内存限制、同24个1秒分片/240帧，各3次顺序对照：

| 中位实测 | CPU | GPU/CUDA |
|---|---:|---:|
| 模型前向/ms每帧 | 52.414 | 5.001 |
| 视频分析累计/s | 15.815 | 5.503 |
| 任务端到端/s | 53.738 | 101.147 |

稳定前向约10.48倍耗时比，端到端尚未加速。单节点受控CUDA模型初始化含预热中位约56.56秒；本轮据实暴露开销，没有把GPU前向加速写成平台整体加速。检测标签/计数一致，舍入后置信度最大差约0.0001，坐标一致。完整条件、单次结果、排除样本与限制见[性能对照](性能对照.md)。

原四lab共享同一RTX5090的24片240帧任务通过；四会话各加载一次模型并回收。故障验证覆盖CUDA不可用明确回退、初始化期间取消、推理期间API/网关重启后原Pod继续执行，全部通过，见lifecycle.json。

## 使用及边界

操作入口和字段说明见[使用说明](使用说明.md)。时间轴空白表示未采集或等待；启动事件可能为秒级精度，模型/分片时长使用单调时钟。GPU前向包含必要的数据传入和输出取回，不能理解为纯内核时长；多节点累计时长不能替代墙钟时间。

仍为一台开发服务器上的四个K3s逻辑节点、共享一张物理GPU，不是4块THOR实机。未实现GPU解码、TensorRT/FP16或跨任务常驻模型；未将CUDA首次预热的原因未经定位地断定为镜像拉取或容器管理。下一步应针对已测出的预热路径定位开销，再决定缓存与复用优化。正式资源池、THOR/ARM64及车载网络仍须到位后验证。
