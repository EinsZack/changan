# CPU/GPU视频任务实测对照

2026年11月10日，0.5.2统一业务镜像。结论：GPU稳定模型前向明显更快，但此次短视频任务端到端仍慢于CPU，主要差别为CUDA首次预热。不能将前向倍率写成平台整体加速。

## 控制条件

同一服务器、原lab-1，同一物理RTX 5090、同一镜像摘要、模型及视频摘要；每次24个1秒分片、请求采样15fps，实际240帧。CPU request=1/limit=2、主机内存request/limit=2048Mi。CPU与CUDA实验都获GPU设备、使用同一通用镜像，仅在隔离任务准备完成且尚未分配时冻结不同模型策略。每次重新创建一个B模式会话，加载一次模型，顺序处理24片并回收；镜像已缓存，未保留跨任务模型或CUDA编译缓存。

顺序为CPU/CUDA、CUDA/CPU、CPU/CUDA，各3次；8310正式任务空闲。后台共享服务器的其他应用没有停止，因此结果只代表本次同机开发环境，不能推断THOR或真实车端性能。

## 三次中位数

| 实测项 | CPU | GPU/CUDA |
|---|---:|---:|
| 模型前向/ms每帧 | 52.414 | 5.001 |
| 视频分析累计/s | 15.815 | 5.503 |
| 任务端到端/s | 53.738 | 101.147 |
| 模型初始化含预热/s | 0.172 | 56.555 |
| 首次前向预热/s | 0.053 | 56.218 |

稳定前向CPU/GPU耗时比约10.48，整任务CPU/GPU耗时比为0.531。三次受控单节点CUDA新会话的首次预热约55～56秒，与毫秒级的后续前向须分开统计；目前未验证该耗时是否由驱动/内核编译缓存或其他初始化路径主导，不能把原因直接断定为镜像拉取。

任务端到端还包括视频切分、容器/程序启动、模型准备、节点领取分片、网络回报、调度间隔、下载及聚合，不能用“总耗时减前向”全部归为容器管理。解码和前后处理仍在CPU。

## 四节点与开发问题

同一RTX 5090由四个原lab共享，四节点GPU功能任务task_62c7937f07c74db7完成24片240帧，4个Pod各加载一次模型。端到端78.188秒，前向累计1.331秒；这是一轮多节点功能验证，不能与上述单节点三次中位数混为一组性能对照。

初始验证task_c7600dacdd514880触及旧1GiB主机内存上限，发生OOMKilled；已统一将新应用CPU/GPU容器预算改为2GiB，同时对齐调度和会话预留，此样本不进入性能统计。测试任务task_c922977bb2a14728由于实验脚本与切片元数据写回竞争，实际运行CUDA而非请求的CPU；已修复脚本同步并重新执行CPU样本，该任务也不进入CPU统计。原始记录保留，见benchmark.json的excluded_development_runs。

## 证据

benchmark.json保存完整条件、六次受控运行、四节点运行及输出一致性；exports/为脱敏原始任务导出（gzip压缩，不含会话/尝试令牌）。real-comparison.png、real-gpu-desktop.png和real-gpu-mobile.png来自真实API数据；fixture截图仅用于网页边界测试，不能充作性能实测截图。对应浏览器报告均注明所用测试配置。

后续如需缩短短任务总耗时，应先针对已测出的首次CUDA预热路径做定位，再考虑节点缓存和跨任务模型复用；本轮保持用户认可的任务内B模式，尚未引入跨任务常驻模型、TensorRT/FP16或GPU视频解码。
