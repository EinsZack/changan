# 车群协同视频分析原型使用说明

版本：0.1.0。更新：2026-09-30。

本说明面向演示操作与开发接续。系统部署在 `root@10.13.0.9:22031` 的 `/root/projects/changan-orchestrator`，代码、运行和测试均在该服务器上完成。本地项目目录只保留计划、文档及展示证据。

## 1 打开系统

在你的电脑终端运行以下命令，并保持该终端打开：

```bash
ssh -N -L 127.0.0.1:8310:127.0.0.1:8310 -p 22031 root@10.13.0.9
```

浏览器打开：<http://127.0.0.1:8310>。

如果8310已被占用，可改为：

```bash
ssh -N -L 127.0.0.1:18310:127.0.0.1:8310 -p 22031 root@10.13.0.9
```

然后打开 <http://127.0.0.1:18310>。服务默认不向公网监听；浏览器通过SSH隧道连接。

页面顶部会标注“开发服务器验证环境”：当前4个执行器都是同一服务器上的独立进程，视频推理与状态回传是真实执行，节点并非4块真实车端板卡。

## 2 第一次运行视频任务

1. 在“运行总览”或“任务中心”点击“新建分析任务”。
2. 保留内置24秒园区测试视频，填写容易识别的任务名称。
3. 选择“全部可用节点”、资源与网络感知或可行节点轮询算法。初次演示建议4秒分片、2帧/秒、置信度0.35。
4. 点击“创建并运行”。系统会生成任务ID，切分6个片段，按资源约束分配给执行器。
5. 在“工作流与执行”观察阶段状态、节点时间轴及“目标/实际节点”。界面每2秒刷新；仅以真实完成片段计数。
6. 所有必要片段成功后进入“分析结果”，查看原视频、识别框、统计与输出来源。
7. 点击“导出证据”或“下载结果及追溯记录”，得到JSON。任务详情API也支持CSV执行记录导出。

视频上传支持OpenCV可解码格式，单文件最大512MB、最长10分钟、分辨率最大4K。浏览器原视频预览建议使用H.264编码MP4；其他容器可能可分析但浏览器无法直接播放。上传校验或格式失败会给出错误，不能将未完成片段视为成功结果。

“高级执行参数”可设置单次尝试超时、最大重试次数及最低可用内存。默认单次尝试90秒、最多重试2次、任务截止600秒。超时应覆盖车端模型实际耗时，真实板卡可能需要调整。

## 3 如何解释结果

当前模型为YOLOX Tiny，使用CPU ONNX Runtime实际推理，支持person、bicycle、car、motorcycle、bus、truck六类目标。当前不使用服务器GPU，页面也不会把8张开发GPU当成真实车端节点。

“行人出现次数”和“车辆出现次数”是采样帧内检测对象数的累加。同一对象跨帧可能被重复统计，不能称为唯一人数或唯一车辆数。未采样帧不计入分析；没有跨片段跟踪或对象去重能力。

每份片段结果保存task_id、segment_id、attempt_id、实际执行节点、模型ID及SHA256。聚合结果只有在全部必要片段成功并核对有效尝试后生成。故障前已经成功的片段可以保留，其余片段按新尝试重试。

## 4 调度依据和基线比较

在任务详情点击“调度决策”，选择一次执行尝试，查看候选节点、排除原因、估计计算时间、传输成本、目标节点和实际执行节点。完整资源快照及算法输入输出可展开查看。

轮询算法先过滤不可执行节点，再在可行节点中选择。资源感知算法使用实测处理吞吐、最近一次HTTP传输速率和占用状态估计完成成本；启动时缺少吞吐数据的节点使用明确标注的初始估计，带宽未测量时不编造带宽。

“候选决策计算”只是单片候选选择耗时，不等于甲方全局调度≤10秒的完整验收指标。事件中另有dispatch_batch记录一轮分配和HTTP提交的实际耗时，统计边界也会一并保存。

做一次可解释的对比：

1. 用同一视频、相同分片时长、采样率和检测阈值提交任务A，执行范围选“仅lab-1”。
2. 参数保持一致，任务B使用全部节点与轮询算法。
3. 参数保持一致，任务C使用全部节点与资源感知算法。
4. 等待成功后，在“历史与对比”选择两次运行。页面核对输入校验值、分片和推理参数，显示耗时比。
5. 记录硬件负载、冷热启动和网络条件。当前测试只是同一服务器多进程对比，不能据此宣称真实车端加速或长期调度成功率达标。

## 5 故障和恢复演示

在“执行节点”可停止某节点的新任务分配，或点击“注入一次失败”。后者仅用于server_process测试模式，下一次真正接收的任务会失败一次；失败尝试、错误原因和替代尝试都会保留。

推荐演示：给4个节点各注入一次失败，再提交视频任务，观察失败尝试后新的attempt_id，以及最终完整聚合。若任务截止或重试上限被耗尽，任务会如实失败。

“取消任务”会停止后续分配，并向执行器发出取消请求。执行器在帧处理边界检查取消。已失联执行器可能暂时仍在运行，旧结果由尝试令牌隔离，不能把取消描述为即时中止所有设备。

开发者可在服务器验证进程恢复：

```bash
cd /root/projects/changan-orchestrator
source /root/miniforge3/etc/profile.d/conda.sh
conda activate changan-orchestrator
python scripts/manage.py restart api
python scripts/manage.py restart worker-1
```

重启管理服务后会从持久化记录核对在途任务。重启执行器会把自身未完成执行标为中断，管理侧据此重试。

## 6 服务和周期触发

在“触发策略”填写名称，选择服务触发或周期触发。周期最小15秒，建议演示时使用60秒以上。保存后的周期策略自动启用；每次运行都有独立任务ID并记录strategy_id。

点击“执行”可通过策略立即触发任务。周期演示结束后点击“停用”，避免持续生成任务。已有验收测试用周期策略已在测试结束后停用。策略参数可通过 `/api/strategies/{id}` 更新，支持工作流默认任务参数和启停。

管理服务重启后保留策略；遗漏周期不会全部补跑，而是在恢复后最多生成一次补偿运行，再按当前时间推进。

## 7 工作流和配置管理

“工作流与能力”提供固定视频模板和五类能力验证模板。点击“运行五类能力验证”会实际执行API、Redis单机读写、内置Python/Shell脚本、调度算法和平台健康接口。逐步输出、耗时和错误都可展开查看。

“配置与算法管理”支持注册、编辑、查询、删除及JSON导出。上传算法配置后，可在新任务的算法下拉框中选择。当前支持的是两个已实现内核的参数化配置，不执行任意上传代码。

API连接器示例：

```json
{
  "url": "http://127.0.0.1:8310/health",
  "method": "GET",
  "auth_id": "none",
  "params": {}
}
```

认证插件示例：

```json
{
  "type": "env_bearer",
  "env_name": "CHANGAN_CONNECTOR_TOKEN"
}
```

认证密钥在服务器环境中设置，不填入JSON配置。每次连接器调用重新读取当前进程环境变量；外部修改启动环境或`.env`后需重启管理服务使新值生效。外部认证服务定时刷新和完整认证管理UI仍是后续项。

## 9 环境复现和验证

要求Linux x86_64、Python3.11 Miniforge环境、Node.js24或兼容版本、npm、curl、make、gcc及网络访问。首次创建或恢复：

```bash
cd /root/projects/changan-orchestrator
bash scripts/bootstrap.sh
/root/miniforge3/envs/changan-orchestrator/bin/python scripts/manage.py start
```

下载不畅时，本服务器交互式Bash提供 `magic on`。可在同一会话开启代理后运行安装。模型、测试素材与Redis源码下载后进行SHA256核对，不自动接受发生变更的资产。

`requirements.lock.txt` 固定Python依赖，`web/package-lock.json` 固定前端依赖，`environment.linux-64.lock.txt` 保存Conda环境包清单。Redis7.2.7编译在项目vendor目录，不依赖其他项目Redis实例。

验证命令：

```bash
python -m pytest -q
python scripts/integration.py
python scripts/benchmark.py
cd web
npm run build
npx playwright install chromium
npx playwright test
```

集成测试和基线测试会真实创建任务、重启本项目执行器/管理服务并产生历史记录；请在本项目无其他在途工作时运行。浏览器首次运行需要系统图形库，已在该服务器安装；其他机器可运行 `npx playwright install-deps chromium`。中文截图使用Noto CJK字体。

## 10 故障排查

- 页面打不开：确认SSH隧道保持连接；服务器执行status，检查logs/api.log。
- 页面提示需要API密钥：若服务器设置了CHANGAN_API_KEY，使用左下角“连接设置”输入；浏览器获得8小时HttpOnly会话，导出与媒体请求共用该会话。
- 节点失联：检查worker日志和模型文件，确认内部令牌一致、端口可达、进程正在运行。
- 任务一直等待：查看事件中的no_candidate及候选理由，检查节点启停、模型、标签、内存条件及截止时限。
- 任务失败：查看尝试错误、超时和重试记录。修改参数后“重新运行”会创建新实例。
- Redis能力验证失败：检查项目Redis8390端口和logs/redis.log；主任务状态保存在SQLite，不依赖Redis缓存。
- 原视频无法播放：优先使用H.264 MP4；这与后端是否可解码分析是两项能力。

## 12 交付包与后续开发

源码包保存在服务器`releases/changan-orchestrator-midterm-0.1.0.tar.gz`，同目录`SHA256SUMS`用于验证整个包。包内`CONTENTS.sha256`可核对每个文件。解压到新目录后使用安装脚本准备依赖和资产，勿覆盖当前运行的`data/`目录。源码包不含模型、视频二进制、Conda环境或运行数据，需要联网恢复资产；当前服务器已具备所有演示依赖。

已建立SSH隧道时，也可通过以下地址下载：

- [源码及交付包](http://127.0.0.1:8310/api/delivery/changan-orchestrator-midterm-0.1.0.tar.gz)
- [SHA256校验清单](http://127.0.0.1:8310/api/delivery/SHA256SUMS)

如改用18310端口，请相应替换链接端口。启用API密钥时先在系统中建立浏览器会话。

校验与解压示例，在服务器的交付包目录执行：

```bash
sha256sum -c SHA256SUMS
tar -xzf changan-orchestrator-midterm-0.1.0.tar.gz
cd changan-orchestrator-midterm-0.1.0
sha256sum -c CONTENTS.sha256
```

后续代码仍在服务器主目录开发，需求、进展与验证结论记录到个人开发计划。其他机器复现时须核对Linux架构、Miniforge位置、Node.js和编译工具；安装脚本在当前已有环境已复跑通过，新机器仍需联合复核。

如需修改管理服务监听地址，可从`.env.example`建立私有`.env`，设置`CHANGAN_HOST`和`CHANGAN_PORT`，并将`CHANGAN_PUBLIC_BASE`同步改为执行器可访问的管理地址。管理脚本在重启时读取这些设置。真实跨机部署需同时设置执行器监听地址、共同内部令牌与资源池网络地址，详见接口说明；不要启动多个协调器。
