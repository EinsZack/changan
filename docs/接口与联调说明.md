# 车群任务编排接口与联调说明

版本：0.1.0。日期：2026-09-30。以下为本模块已经实现的接口契约，资源池同学尚未确认或接入；不能视为双方已经冻结的协议。

## 1 服务和事实来源

管理服务持有任务、片段、执行尝试、策略、事件和聚合结果的持久化记录。执行器持有其执行状态和产物。资源池正式接入后，应作为资源快照、可用资源和资源预留的权威来源。

管理API默认监听127.0.0.1:8310，四个测试执行器监听8321—8324，Redis监听8390，均限服务器回环地址。浏览器每2秒刷新后台记录，显示的是实测事件与完成片段数。

OpenAPI：运行后访问 `/docs` 或 `/openapi.json`。本交付保存 `openapi.json` 作为当前接口快照。服务只允许一个管理进程，不得以多个Uvicorn worker运行协调器。

## 2 任务接口

| 方法与路径 | 行为 |
|---|---|
| POST /api/uploads | multipart上传视频，最大512MB，视频最长10分钟；返回source标识 |
| POST /api/tasks | 创建任务，可使用Idempotency-Key防止重复提交；同键不同参数返回422 |
| GET /api/tasks | 查询历史，支持status、q、workflow_id、node_id、after、before、limit |
| GET /api/tasks/{id} | 返回任务、片段、尝试、决策和结果 |
| POST /api/tasks/{id}/cancel | 持久化取消，核对和请求取消执行器上的任务 |
| POST /api/tasks/{id}/rerun | 创建新的运行实例，保留旧记录 |
| GET /api/tasks/{id}/events?after=0 | 查询事件序号之后的事件，单次最多1000条 |
| GET /api/tasks/{id}/export | 导出任务、事件、结果及追溯信息；format=csv导出尝试表 |
| GET /api/overview | 状态汇总、工作流维度及上海时区按日统计 |
| GET /api/tasks/{id}/video | 原视频 |
| GET /api/tasks/{id}/artifacts/{attempt}/{name} | 已保存的识别预览图片 |

创建任务示例：

```json
{
  "name": "园区视频协同分析",
  "source": "demo",
  "algorithm": "resource_aware",
  "segment_seconds": 4,
  "sample_fps": 2,
  "confidence": 0.35,
  "priority": 0,
  "deadline_seconds": 600,
  "attempt_timeout": 90,
  "max_retries": 2,
  "min_memory_mb": 256,
  "node_ids": [],
  "required_tags": [],
  "architecture": null,
  "location": null,
  "workflow_id": "video-analysis"
}
```

单位：视频区间和截止时间使用秒，事件时间为Unix秒，HTTP延迟为毫秒，接口内存使用MiB字段名memory_mb，带宽bandwidth_mbps使用十进制Mbit/s。与资源池联合冻结时必须明确MiB换算，禁止混用字节与MiB。

算法与工作流配置在创建任务时保存快照；后续修改配置不会悄悄改变已创建运行。

## 3 执行器协议

所有执行器接口及管理侧 `/internal/*` 使用 `X-Internal-Token`。令牌由环境变量或项目数据目录权限0600的文件提供，不包含在任务导出或版本库中。

| 接口 | 语义 |
|---|---|
| GET /health | 节点ID、模型、架构、运行时、执行槽、资源观测时间及吞吐 |
| POST /executions | 按attempt_id幂等接收；target_node必须等于自身NODE_ID；已满返回409 |
| GET /executions/by-attempt/{id} | 下发响应丢失后按幂等键核对，404才说明未接收 |
| GET /executions/{id} | 持久化执行状态和结果 |
| POST /executions/{id}/cancel | 取消请求；在推理帧边界检查取消 |
| GET /executions/{id}/artifacts/{name} | 获取result.json及受限预览图 |
| POST /controls/fail-once | 仅server_process模式提供的显式故障注入 |

提交包含task_id、segment_id、attempt_id、target_node、token、input_url、input_sha256、callback_url、params。输入通过HTTP获取并验证SHA256，结果关联实际执行节点和模型哈希。返回执行ID、状态、递增seq、进度和关联字段。

状态为ACCEPTED、RUNNING、SUCCEEDED、FAILED、CANCELED。管理侧额外记录DISPATCHING、UNKNOWN和TIMED_OUT。执行器把状态变化回传 `/internal/events`，回调失败时，管理侧周期查询持久化状态补齐。进度为实际已处理帧对应的视频位置，不是计时动画。

管理侧验证节点、任务、片段、尝试令牌和事件序号；旧尝试、重复事件、迟到结果不能覆盖当前有效结果。每个片段所有必要结果完成且聚合校验通过后父任务才成功。失联超过上限后可以重试，但旧执行可能仍在运行，采用至少一次执行和结果幂等，不声称严格一次执行。

## 4 资源池适配协议

未配置 `CHANGAN_RESOURCE_PROVIDER_URL` 时，开发模式从执行器读取共享服务器观测数据，并以本地持久化预留加执行器原子接收防止重复占用。

配置该变量后，管理侧通过以下接口读取和预留资源。可选 `CHANGAN_RESOURCE_PROVIDER_TOKEN` 以Bearer方式认证。外部资源服务不可用时不静默退回开发快照。

### GET /nodes

返回数组：

```json
[{
  "node_id": "vehicle-1",
  "healthy": true,
  "observed_at": 1790700000.0,
  "snapshot_version": "v100",
  "available_memory_mb": 4096,
  "bandwidth_mbps": 100,
  "network_source": "资源池实测",
  "architecture": "aarch64",
  "location": "yard-a",
  "tags": ["cpu", "onnx"]
}]
```

节点身份和执行通道先通过 `POST /api/nodes` 注册，字段为id、endpoint、cluster_id、kind。kind支持server_process、vehicle、simulated；登记为vehicle不等于硬件已经验收。资源池快照补充资源、网络、标签等字段，健康同时要求执行器和资源池均健康；观测时间超过8秒不参与新分配。

### POST /reservations

提交node_id、task_id、attempt_id、idempotency_key、requirements、snapshot_version、lease_seconds。requirements包含memory_mb、slots。成功返回 `{"reservation_id":"lease-1"}`，资源竞争时返回409。

资源服务必须原子核验资源与快照版本，并按幂等键返回同一预留。当前任务尝试超时前不续租，租期设置为attempt_timeout+30秒；因此本原型每次执行须在所设超时内完成。若预留后管理侧崩溃、请求响应丢失或取消竞争导致预留未持久化，依赖租约自动到期清理。

### DELETE /reservations/{id}

终态尝试触发释放，释放成功写入决策记录；404作为已释放处理。管理服务重启后继续扫描未释放记录。

此适配已通过模拟HTTP契约测试，未与真实资源池服务联调，也未验证真实资源池的原子性、租约和故障语义。

## 5 车端联调步骤

1. 确认板卡、架构、Linux版本、CPU/加速器运行时和网络可达性。
2. 先在一个节点验证ONNX模型输入输出；若需TensorRT/NPU，新增或替换Detector适配，保持结果协议。
3. 部署执行器，配置唯一NODE_ID、NODE_KIND=vehicle、令牌、工作目录和内网监听地址。管理侧配置可被车端访问的CHANGAN_PUBLIC_BASE。当前脚本默认回环监听，跨机前须按组内网络方案配置，不直接暴露公网。
4. 注册节点endpoint、cluster_id和kind，核对目标节点与回执实际节点。
5. 接入资源池快照和预留协议，验证空闲、忙碌、失联、恢复与并发竞争。
6. 从单节点扩展至4个真实车端，管理节点不计入4个算力节点。核对拓扑、校时、视频传输和板卡日志。
7. 在一致输入和模型下开展正常、带宽变化、资源冲突、失联与恢复测试，保存原始记录。

## 6 中期管理能力边界

`/api/strategies` 支持创建、编辑、删除、启停、服务触发和周期触发。策略关联固定视频工作流；进程重启后从SQLite恢复，遗漏周期合并为恢复后一次执行，不追补所有历史周期。

`/api/configs/{category}` 管理algorithm、workflow、connector、auth配置。algorithm上传的是已实现算法内核的JSON参数清单，不是任意可执行代码插件；两种内核为round_robin与resource_aware。

API连接器支持GET/POST、入出参键映射、注册、更新、查询、删除和JSON导出。认证支持none与env_bearer插件；凭据只能由CHANGAN_CONNECTOR_前缀环境变量提供，每次调用重新解析当前进程环境；更改外部启动环境后需重启使其生效。外部认证服务定时刷新、复杂映射和认证平台页面属于后续完善项。

五类模板验证真实执行API、Redis单机读写、内置Python/Shell脚本、调度算法和执行平台接口。Kafka、多模式Redis、任意脚本库管理、完整拖拽DAG设计及应用生命周期管理不在当前已完成能力中。
