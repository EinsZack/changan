# 三Thor平台部署与使用说明

更新时间：2026年11月13日。Mac继续原生运行平台和OCI仓库，真实执行节点为Thor1、Thor2、Thor3。

## 使用入口

Mac保持192.168.50.x局域网，当前IP为192.168.50.231。打开`http://127.0.0.1:8310/?release=20261113-thor3`，新建任务时选“全部可用节点”，当前包含三板；选择“仅thor3”可做单板任务。复现本轮三板任务使用24秒内置视频、1秒分片、10fps采样，算法选可行节点轮询或资源与网络感知。

任务详情中检查：24/24分片、240采样帧、三个实际节点的时间轴、每节点CUDA会话及独立Pod、模型各加载1次、回收3/3、真实检测预览。各板处理分片数量可以受实际启动和执行时序影响，不应人为均分或伪造进度。

## SSH与板端服务

Mac公钥已授权Thor3，日常连接：

```bash
ssh -o ServerAliveInterval=30 -o ServerAliveCountMax=3 thor3@192.168.50.153
```

SSH仅用于运维，关闭终端不会停止systemd服务。本轮已验证关闭初始SSH后k3s-agent继续运行；断线后重新执行SSH命令即可。

```bash
# 在Thor3查询
systemctl is-active k3s-agent
systemctl is-enabled k3s-agent
sudo journalctl -u k3s-agent -n 50 --no-pager
# 仅在服务异常且无业务在途时恢复
sudo systemctl restart k3s-agent

# 在Thor1查询整个集群
sudo k3s kubectl get nodes -o wide
sudo k3s kubectl get pods,jobs -n changan
```

Thor1是K3s server兼执行节点；Thor2/3是agent。普通SSH断开不需要重启Thor1控制面。

## Mac重启后启动

Mac使用已有Miniforge项目专用环境，不需要容器引擎。登录用户会话后执行：

```bash
source /opt/homebrew/Caskroom/miniforge/base/etc/profile.d/conda.sh
conda activate changan-platform
python "/Users/eins/Library/Application Support/ChanganPlatform/current/scripts/install_native_services.py" \
  --root "/Users/eins/Library/Application Support/ChanganPlatform" \
  --env-prefix "/opt/homebrew/Caskroom/miniforge/base/envs/changan-platform" \
  --gateway-host 192.168.50.231
```

脚本可重复运行。API/网关仍在用户会话后台运行，无故障自动拉起；Redis、Zot和防空闲睡眠服务使用LaunchAgent。caffeinate不保证合盖后的联网。Mac、Thor的DHCP固定租约尚未配置；地址变化需检查网关、仓库、证书及K3s连接配置。

## 复跑验收

在没有其他在途任务时执行，使用独立新输出目录保存新证据：

```bash
conda activate changan-platform
python "/Users/eins/Library/Application Support/ChanganPlatform/current/scripts/validate_thor_cluster.py" \
  --root "/Users/eins/Library/Application Support/ChanganPlatform" \
  --nodes thor1 thor2 thor3 \
  --output "/Users/eins/Library/Application Support/ChanganPlatform/data/evidence/thor-triple-recheck" \
  --cancel
```

该命令实际上传视频并新增4条任务：Thor3独立执行、三板轮询、三板资源感知、三板运行中取消。要求每个指定节点Ready、有GPU且物理身份不同。只验证Thor3时传`--nodes thor3`，省略`--cancel`并使用另一独立输出目录。

## 接入配置与排查

Thor3配置位于`/etc/rancher/k3s/`：config.yaml指向Thor1的6443端口，node-name为thor3、node-ip为192.168.50.153、flannel-iface为wlP1p1s0；加入凭据使用root所有、600权限的独立agent-token文件。registries.yaml配置Mac仓库HTTPS端点与mac-registry.crt。CUDA缓存位于`/var/lib/rancher/k3s/changan-cache/cuda`，UID/GID10001、700。

业务标签均在`changan.io/`前缀：node-id=thor3、physical-host=thor3、kind=vehicle、slots=1、memory-mib=65536。后者为调度预算，非实时采集。板卡序列号摘要注解与Kubernetes节点UID辅助核验物理身份；三板GPU UUID相同，不用于去重计数。

断联时先检查Mac仍在192.168.50.x，再检查ping与SSH、Thor1的6443端口、对应板端systemd及Mac平台进程。网页可开但节点离线时优先检查网络和agent；网页打不开时按上面Mac启动命令恢复。保留原数据库与证据，不通过删除历史数据或重装整个集群排障。
