# 任务详情传输与吞吐统计使用说明

交付日期：2026年10月31日。基于0.2.0原型增加任务详情展示，统计来源沿用已有任务结果和调度快照。

## 打开方式

1. 刷新现有网页，进入“任务中心”。
2. 点击一条任务，进入“任务详情”。
3. 点击“传输与吞吐”页签。
4. 上方查看输入量、平均接收速率、平均处理吞吐和有效结果片段数；下方查看片段明细及调度时网络观测。
5. 如需原始字段，使用详情页的“导出证据”。旧任务只要保留相应记录即可显示，无需重新执行。

## 指标与口径

| 展示 | 来源和计算方式 |
|---|---|
| 已记录输入量 | 当前有效尝试成功结果中的 input_bytes 之和；分别显示具备记录的片段数量 |
| 片段平均接收速率 | 同时具备输入字节数和有效下载耗时的片段，按总字节数 × 8 ÷ 下载耗时之和 ÷ 1,000,000计算，单位Mbit/s |
| 片段平均处理吞吐 | 同时具备采样帧数和有效处理耗时的片段，按采样帧数之和 ÷ 处理耗时之和计算，单位帧/s |
| 片段执行实测 | 实际执行节点、输入量、下载耗时、计算出的平均接收速率、执行器回传的measured_fps |
| 调度时网络观测 | 每次执行尝试保存的目标节点快照时间、HTTP往返耗时、最近片段下载速率、预计传输耗时及来源 |

1 KiB = 1024 B，1 MiB = 1024² B，1 Mbit/s = 1,000,000 bit/s。下载耗时包含请求与落盘；处理耗时涵盖视频解码、采样推理及结果整理。计算速率时与执行器一致，将小于1毫秒的正耗时按1毫秒处理；零耗时、负值、非数字和缺失值不参与速率汇总，页面保留“—”。

只统计每个片段的当前有效成功结果，重试与旧尝试不会重复计数。任务尚未全部完成时，可以查看已成功片段的数据；卡片显示各指标实际参与计算的片段数。并行片段耗时相加，汇总值不代表任务并发总带宽或端到端吞吐。

网络快照为调度当时的历史观测，可能来自此前任务；不使用节点当前值覆盖，也不与本次下载实测混用。当前只具备输入下载方向统计，结果回传方向、网卡累计收发量和连续速率曲线仍未实现。

## 复核命令

在服务器项目根目录执行：

```bash
cd web
node --test tests/taskMetrics.test.js
npm run build -- --outDir ../tmp/task-metrics-web-dist --emptyOutDir
npx playwright test -c playwright.metrics.config.js
cd ..
TMPDIR=/dev/shm /root/miniforge3/envs/changan-orchestrator/bin/python -m pytest -q
```

告警回归需先将本次构建复制到 tmp/alerts-web-dist，再使用专用环境Python运行 web/playwright.alerts.config.js；该配置创建隔离数据库。默认浏览器配置排除告警与统计专用测试，避免误将隔离用例跑到现有服务上。
