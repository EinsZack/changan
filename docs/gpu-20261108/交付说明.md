# GPU 容器执行升级交付说明

2026年11月8日 · 版本 0.6.0 · 方雍主责任务编排、调度与协同执行

## 交付结果

服务器 `/root/projects/changan-orchestrator` 已完成 GPU 容器执行迭代并切换正式服务。新任务默认选择 CUDA，也可显式选择 CPU。现有 B 模式保持：一个任务在一个节点保留一个容器和模型，连续处理视频分片，任务结束后回收。

开发集群保留四个 CPU 逻辑节点，并新增 `gpu-1`，对应服务器上一张真实 RTX 5090。NVIDIA 运行时、设备插件、K3s GPU 请求、ONNX CUDA 推理已打通。该显卡仍与服务器其他进程共享，不将多个逻辑节点重复登记为同一张 GPU，也不把服务器节点计为 THOR 实机。

## 四项开发内容

| 方向 | 本次实现 |
|---|---|
| GPU 推理 | 独立 CUDA 镜像；明确选择 CPU/CUDA；检查设备 UUID、可见设备数量、实际执行提供程序及预热中的 CUDA 计算事件。整模型禁止静默回退 CPU。 |
| GPU 调度 | GPU 数量、占用预留、空闲显存、运行环境、遥测时效和镜像架构参与筛选；重复 GPU UUID 阻止分配；CPU/CUDA 吞吐分开记录并匹配模型和镜像；资源池预留参数增加 GPU 字段。 |
| 容器与模型复用 | 保持任务内会话，GPU 按会话占用；分片完成不释放 GPU；取消及异常按实际清理结果释放；控制面重启继续使用原 Pod，Pod 中断后只重排未完成分片。 |
| THOR 准备 | 按 amd64/arm64 冻结不同镜像摘要，提供板端只读预检、ARM64 镜像模板、依赖和资源接口说明。硬件/BSP/CUDA/cuDNN 版本到位后确定。 |

页面增加后端选择、显存需求、GPU 状态、实际 CUDA 证据和模型计算计时；原传输统计继续保留。业务镜像非 root、只读根文件系统。服务器驱动未替换，其他 GPU 进程未被终止。

- **8 项前端统计测试、5 项统计浏览器夹具测试通过**。

- **7 个真实 K3s 集成场景通过**，详细任务与镜像摘要见 `integration-report.json`：

| GPU 连续 24 分片、240 帧 | 1 会话、1 Pod、模型加载 1 次，24 片全部完成并回收 |

预验证期间一次脚本读请求超时，后台视频任务仍完成；另修正了验证脚本读取结果位置及整数事件 ID 与 JSON 字符串键的比较方式。最终报告来自修正后的完整验证；没有修改历史数据来通过检查。

## 性能与数值对照

在同一个 CUDA 镜像、同一个节点和相同 2 CPU 限制下，对同一视频的 12 帧进行 CPU/CUDA 各 3 轮比较。输入帧统一缩放到 512×384 并 JPEG 编码；模型为 YOLOX Tiny 416，置信度 0.35，FP32，TF32 关闭。

| 测量项 | CPU | CUDA |
|---|---:|---:|
| Session.run 中位耗时 | 48.82 ms/帧 | 2.82 ms/帧 |
| 含图像前后处理的检测中位耗时 | 51.89 ms/帧 | 4.89 ms/帧 |
| 本次模型加载和预热 | 0.22 s | 10.94 s |

两后端各输出 112 个检测结果，当前输出精度下框与置信度一致（框按 0.1 像素、置信度按 4 位小数输出）；这是后处理输出比较，不等于完整原始浮点张量逐位一致。原始逐轮计时和检测结果在 `benchmark.json`。

模型计算中位耗时约缩短到原来的 1/17.3。该数值**不是端到端加速倍率**。正式单节点 6 分片、48 帧任务，本次 CPU 总耗时 21.81 秒、CUDA 28.74 秒，CUDA 未在这一短任务上取得更短总耗时；它包含首次预热、控制面调度、视频处理和网络请求。当前视频解码及前后处理仍在 CPU。后续可依据长视频/板卡实测评估预热缓存、调度周转和硬件编解码，不能以本次模型测试代替整个平台或真实车端性能结论。
