# 站内任务告警使用说明

版本：0.2.0

日期：2026年10月31日

任务超期或最终失败后，平台保存一条站内告警，并在网页顶部显示未读数量。打开“站内告警”可查看原因、触发时间、任务截止时间和触发时已完成的片段数。

## 触发规则

| 规则 | 条件 | 级别 |
|---|---|---|
| 任务超期 | 任务超过提交时设置的 deadline_seconds，被协调器置为 TIMED_OUT | 警告 |
| 任务执行失败 | 准备、执行或聚合最终失败，父任务进入 FAILED | 错误 |

任务的截止时限从创建时计时，覆盖排队、切分、调度、执行和聚合；它与调度决策计算耗时是不同的指标。告警随实际终态写入，不预测未来超时，也不自行更改截止时限。

执行尝试失败后仍可重试时不立即生成任务级告警。成功任务和用户主动取消不触发上述规则。同一任务至多一条告警；重复回调和重复终态处理不会重复通知。

本版开始记录部署后的新异常。升级前已结束的任务保留原有历史查询，不批量补发告警。

## 网页操作

1. 顶部铃铛及导航菜单显示未读数。有未读告警时，其他页面显示提示条。
2. 点击铃铛、提示条或“站内告警”进入列表。默认显示待确认记录，可按处理状态、阅读状态和类型筛选，每页20条。
3. 点击“查看任务”进入原任务，查看工作流、执行记录、失败原因或事件。
4. “标为已读”只清除该条未读标记，告警仍待确认。
5. “确认告警”同时标记已读和已确认，并保存时间。它记录对提醒的处理，不改变原任务失败或超时结果。
6. 确认后的告警可切换“已确认”或“全部状态”查阅。刷新页面和重启管理服务保留记录。

需要重新执行时，在任务详情使用已有重新提交功能，生成独立任务。新任务结果与原告警分别保存，不把重跑成功写成原任务自动恢复。

当前原型使用共享的阅读和确认状态，尚未引入按用户独立的消息收件箱。规则由本版固定实现。网页每2秒查询一次状态；服务器阻塞或网络异常时显示可能延迟。当前不发送邮件、短信或其他站外通知。

## 接口

| 方法与路径 | 用途 |
|---|---|
| GET /api/alerts | 分页查询告警，同时返回全局 total、unread、open 数量 |
| GET /api/alerts/rules | 查询本版两条固定规则 |
| POST /api/alerts/{id}/read | 幂等标为已读 |
| POST /api/alerts/{id}/acknowledge | 幂等确认，同时标为已读 |

列表参数：status=open或acknowledged、unread=true或false、rule=task_timeout或task_failed、task_id、limit（1—100，默认20）、offset（非负）。items和total服从筛选，summary为全局计数。列表排序为触发时间及告警编号倒序。

所有接口复用现有API密钥/浏览器会话与跨站修改校验。告警保存在管理侧SQLite的alerts表。任务终态、告警和关联事件在同一事务中提交；任务编号唯一约束用于防重。确认操作记录alert_acknowledged事件。

## 部署与复测

在服务器项目专用环境中：

```bash
python -m pytest -q
cd web
npm run build -- --outDir ../tmp/alerts-web-dist --emptyOutDir
npx playwright test -c playwright.alerts.config.js
```

浏览器专项验证通过scripts/serve_alert_tests.py启动18310端口的独立管理服务，使用临时数据库和禁用的测试节点。超时案例实际切分示例视频后因无候选等待截止；失败案例使用明确损坏的测试输入。测试不向现有执行器下发任务，也不修改运行环境的节点或任务。测试结束后清理临时数据。

发布前备份管理数据库并核对没有在途任务。将已验证前端构建发布至web/dist后，仅重启管理API：

```bash
python scripts/manage.py restart api
```

已有管理数据库会在启动时自动增加alerts表及索引，不删除历史任务。CHANGAN_WEB_DIR可指定静态资源目录，默认仍为web/dist；专项测试用它加载隔离构建。
