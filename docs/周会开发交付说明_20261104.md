4. 在任务详情“视频与片段”中选择片段4，播放尾片；源视频与片段分别显示时长。
5. 点击“失联核对”查看已记录的影响范围、最后状态、通信恢复与任务核对时间。

## 新增接口

| 方法与路径 | 作用 |
|---|---|
| `POST /api/scheduling/candidates` | 根据params、duration_seconds、input_bytes返回候选、筛选理由及数据来源 |
| `GET /api/node-incidents?task_id=...` | 查询失联记录、影响任务/片段和当前执行尝试状态 |
| `GET /api/sources/{source}/video` | 上传后回放源视频，支持Range |
| `GET /api/tasks/{task_id}/segments/{segment_id}/video` | 按所属任务读取生成片段，支持Range |

下发请求事件为 `dispatch_request`，确认事件为 `dispatch_ack`。请求中记录 `task_id`、`segment_id`、`attempt_id`、`target_node`、`input_sha256`、`input_bytes`、`params`；确认记录 `actual_node`、`execution_id`、`state`、`identity_matched`。事件不保存执行令牌。

失联记录中 `link_restored_at` 表示再次成功读取节点快照，`task_reconciled_at` 表示受影响尝试均已核对到有效状态。两者分别落盘，页面时间按秒显示。
